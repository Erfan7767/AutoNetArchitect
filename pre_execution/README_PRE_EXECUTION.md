# Pre-Execution Governance

هذه الطبقة تحسم قرارات V1 قبل كتابة كود المنتج. وهي مكملة لـ `execution_protocol/`: فـ `pre_execution` يعرّف **ما الذي نبنيه وتحت أي قيود**، بينما يعرّف `execution_protocol` **كيف ننفذ المراحل ونتحقق منها**.

## القرارات المحسومة

| المجال | قرار V1 |
|---|---|
| المنتج | منصة single-user لتصميم شبكات اتصالات، توليد مواصفات قابلة للمراجعة، والتحقق في مختبر قبل أي deployment |
| نمط التشغيل | Single-user، local-first، مع عدم افتراض حسابات أو تعدد مستأجرين |
| مصدر الحقيقة | العقود والـ schemas والإعدادات المعتمدة؛ مدخلات الإنسان الموسومة إلزامية |
| الأتمتة | القراءة والتحليل والتوليد المقترح مسموحة؛ التغيير التشغيلي يحتاج موافقة صريحة |
| vendors | Huawei في V1 ضمن مكتبة الأجهزة المعتمدة؛ أي vendor آخر يحتاج قرارًا جديدًا |
| deployment | لا تنفيذ مباشر افتراضيًا؛ dry-run، diff، backup، approval، وrollback إلزامية |

أي معلومة غير مؤكدة ميدانيًا يجب أن تظهر كـ `HumanSuppliedMandatory` أو `Assumption`، ولا يجوز تحويلها إلى حقيقة ضمنية.
